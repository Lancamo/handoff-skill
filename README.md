# handoff — 对话换窗交接

面向「非专业程序员 + Vibe Coding」用户的会话窗口切换与管理工具。把换窗从十几步手工操作压成一句话 `/handoff`：**信息不丢、思维连续、过程简单**。

## 为什么需要它

### 长对话必然退化

非专业用户习惯用自然语言模糊描述 + 多轮迭代微调，以"能用、看着对"而非代码质量作为验收标准，于是超长对话成了必然。但 AI 在超长对话中会退化：

- **上下文漂移**：忘记交互约定，乱说英文、脱离既定交流语言
- **响应变慢**：每轮都要重读全部历史，反馈时间越来越长
- **指令被稀释**：早期确认的偏好与标准被遗忘，很小的需求也翻来覆去改不对

结果：项目难以推进，还无谓消耗 Token。

### 换窗交接是最难的一步

对话退化到必须换新窗口时，交接偏偏要求"把当前状态写清楚"——做到哪、为什么这么做、下一步干嘛。**这正是非专业程序员最难承担、也最容易中断的一步**：要么硬撑一个坏掉的对话，要么信息在新旧窗口之间丢失。

### 用户信息与项目信息同等重要

对非专业用户，"你是什么样的人、喜欢怎么配合、怎么判断做对了"（能力画像与协作偏好）和项目技术信息同等重要，却最容易在换窗时丢失。handoff 把这一层一并交接。

## 设计理念

1. **文档是硬盘，上下文是工作台**：仓库（文件系统）始终完整，工作台（对话）始终清爽。交接靠文档，不靠 AI 的记忆。
2. **尽可能不切换**：换窗由健康信号 + 里程碑从严判定，不预设轮数；skill 只提醒、不自动执行。
3. **系统承担复杂性**：用户只确认，不复制粘贴、不手写交接文档。
4. **地图不是领土**：交接文档只告诉新会话"去哪里读什么"（文件索引），不搬运全部文件内容。

## 核心机制

一次换窗，由 skill 自动完成整个闭环：

```
旧窗口（长对话退化）──/handoff──▶ 生成交接文档 ──▶ 新窗口 ──/handoff──▶ 自动接手
```

- **三层交接结构**：交接文档分「全貌 / 阶段 / 交接」三层。新窗口先读全貌（项目是做什么的），再核对阶段（做到哪、下一步），最后处理交接（最要紧的坑与待办）——旧窗口写、新窗口报，同一套结构，信息不因换窗而漂移。
- **交接文档**：纯 Markdown，随项目存进 `Handoffs/`，git 跟踪、历史可审计。
- **健康信号**：上下文接近上限、语言漂移、节奏变慢、改动面异常扩大、重复说明等，从严判定是否提醒换窗——只提醒、不自动。
- **只确认、不抄写**：过程静默，所有需要拍板的地方压成一次多选点选，其余由 skill 承接。

### 三种模式

| 模式 | 触发 | 做什么 |
|------|------|--------|
| **模式 A · 切换前** | 旧窗口输入 `/handoff` | 静默采集、按三层提炼，生成交接文档，弹一次多选确认，简洁收尾 |
| **模式 B · 接手** | 新窗口输入 `/handoff` | 列出含交接文档的项目等你点选 → 读三层 → 复述概况 → 让你点选开工方向 |
| **模式 C · 存档** | 里程碑确认后 | 更新交接文档的已完成项（附验证结论）、下一步、关键决策 |

## 适用场景

| 场景 | 说明 |
|------|------|
| 换窗续接 | 对话太长或变慢时，换新窗口接着做，信息不丢 |
| 跨设备续接 | 这台电脑做到一半，换台电脑继续，交接文档随项目走 |
| 跨工具切换 | 在 Claude、Codex 等不同 AI 工具之间切换，交接文档都能被接手 |
| 阶段交接 | 开发做完，把项目连同交接文档交给验收/测试环节（人或 AI） |

## 安装

```bash
# 把 skill 放进 Claude Code 技能目录
mkdir -p ~/.claude/skills/handoff
cp -R SKILL.md templates/ ~/.claude/skills/handoff/
```

重启 Claude Code 后，输入 `/handoff` 即可使用。

## 使用

| 场景 | 操作 |
|------|------|
| 换窗续接 | 旧窗口 `/handoff` 生成交接文档 → 新窗口 `/handoff` 点选本项目即可接手 |
| 里程碑存档 | 进行中输入 `/handoff`，更新交接文档 |
| 跨设备 / 跨工具 | 交接文档随项目进 git，任何工具、任何设备可接手 |

handoff-skill/
