## 2. 共享红线（全部模块适用）

1. **交流语言**：与用户对话默认使用其交流语言；代码、变量名、commit message 用英文。
2. **外科手术式修改**：只改必须改的，每行改动可追溯到请求；发现无关死代码只指出不删除。
3. **密钥红线**：真实 key 只进 config.local 类文件或环境变量（gitignore）；测试一律用 fake server。
4. **git**：commit message 英文祈使句；push 仅用户本人执行。
5. **预览与截图**：启动开发服务器、浏览器截图前必须征得用户许可。
6. **测试是交付前置条件**：全绿 + 附运行输出证据，不接受"看起来没问题"。
7. **发现问题先上报**：先报告再定方案，不默默堆兜底代码。

## 3. 工作流约定

- 新任务第一步：读对应模块规则文件，再动手。
- 计划文档放计划文件夹（如 `Plan/`）；命名 `序号_版本_描述`；执行完把验证结论写回。
- 换窗交接文档放 `Handoffs/`（进 git）；命名 `序号_版本号_handoff.md`；用 /handoff 生成与接手。
- 上下文约 80% 主动压缩并检查摘要。
- 里程碑打 tag。
